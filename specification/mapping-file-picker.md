- **File Picker (`editor.file-picker`):** Helix’s file picker config controls ignoring hidden files, following symlinks, etc. in its built-in picker. In Neovim, a “file picker” might be implemented via **Telescope**, **fzf-lua**, or similar plugins. We plan to integrate these options as follows:

  - `hidden`: If false (Helix default true means ignore hidden), we exclude hidden files from search results. For Telescope, we can pass `find_command` options to ignore `.*` files or use `no_ignore` flags. If `hidden = true` (meaning do not ignore hidden), we configure the picker to include hidden files (e.g. `telescope.find_files(hidden=true)`).
  - `follow-symlinks`: If true, ensure the file picker follows symlinks (Telescope by default does, but we can confirm or set `fd`/`find` flags). If false, we might add `-P` or equivalent to not follow symlinks.
  - `deduplicate-links`: If false, the Helix picker would list duplicate symlinked files separately; if true (default), skip those. Telescope doesn’t typically list duplicates, so this may not need special handling, or we could implement by filtering results.
  - `parents`, `ignore`, `git-ignore`, `git-global`, `git-exclude`: These determine whether ignore files in parent directories, `.ignore` files, `.gitignore` files, etc. are respected. Many fuzzy finders respect .gitignore by default. We might need to configure our picker to use rg (ripgrep) with `--no-ignore-parent` or similar flags depending on these booleans. This is an advanced use case: for an initial implementation, we might assume defaults (which correspond to Helix’s default true for all these).
  - `max-depth`: Limit recursion depth. We can incorporate this by passing `-maxdepth` to find or appropriate option to the search command if user sets it.
  - Implementation: likely, we will not write a custom picker, but if the user has Telescope, we provide a wrapper or configuration. For example, our layer could define a custom Telescope command or override `Telescope find_files` defaults via its setup to match these preferences (using telescope’s `defaults.file_ignore_patterns` for ignores, etc.). Documentation for the config layer will note that these options take effect only if using a supported picker plugin.
