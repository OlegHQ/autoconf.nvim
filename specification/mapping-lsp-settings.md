- **LSP Settings (`editor.lsp`):** Helix’s `[editor.lsp]` section toggles certain LSP client behaviors. We map these to Neovim’s LSP client and UI configuration:

  - `enable`: If false, the entire LSP integration is disabled. Our layer will then **not launch any LSP servers** even if defined in `languages.toml`. We will skip setting up nvim-lspconfig for any language. (In practice, `sys.languages` will check a flag set by `sys.config` and avoid starting LSPs if disabled.)
  - `display-messages`: Helix true/false for showing `window/showMessage` from LSP. In Neovim, by default such messages show up as notifications or in `:messages`. To simulate disabling them, we can override the LSP handlers for `"window/showMessage"` to a no-op if `display_messages = false`. If true, leave default (which typically prints to cmdline or opens a dialog if using a plugin like nvim-notify).
  - `display-progress-messages`: Controls showing LSP progress (like `$/progress` notifications). If false (default), don’t show progress. In Neovim, this can be mapped to either not using a progress UI or disabling any plugin that would show it. If using lualine, the spinner element in statusline is one form of progress indicator. We could simply honor this by not enabling such an indicator if false.
  - `auto-signature-help`: If true, show function signature help automatically when appropriate. To implement this, we can use a plugin like **lsp_signature.nvim** or Neovim’s built-in LSP events. For example, we could set up an autocommand on `CursorHoldI` (cursor hold in insert mode) or on trigger characters to call `vim.lsp.buf.signature_help()` when this is true. If false, only show signature help on explicit command (which is default Neovim behavior).
  - `display-inlay-hints`: If true, enable LSP inlay hints. Neovim 0.10+ supports inlay hints natively via `vim.lsp.inlay_hint()` API. We will call this for attached servers if the user enables it. If on an older Neovim, we could integrate a plugin like **lsp-inlayhints** to render them. The layer will ensure to activate inlay hints after LSP attaches for relevant servers when this flag is true.
  - `display-signature-help-docs`: If true, show documentation in the signature help popup. The plugin `lsp_signature.nvim` has an option for showing the doc lines in the popup; we can toggle that. If using only Neovim default, this might correspond to doing nothing special (Neovim’s signature help floating window by default shows docs if available). If false, we might configure `lsp_signature` plugin to hide documentation.
  - `snippets`: If false, disable snippet completion from LSP. If the user doesn’t want snippet suggestions (like VSCode-style snippet completions from LSP), we can filter those out in completion. If using **nvim-cmp** for completion, for example, we could remove the `luasnip` source or configure the LSP capabilities to not include snippet support. This might be advanced to implement fully; we can note that if `snippets=false` we will advertise to LSP that we don’t support snippet insertion (set `client.server_capabilities.completionProvider.resolveProvider = false` for snippets or similar).
  - `goto-reference-include-declaration`: If false, we should exclude declaration from “go to reference” results. In Neovim, the `vim.lsp.buf.references()` by default includes declarations depending on LSP server settings. We can handle this by passing an appropriate parameter if available (some LSP allow includeDeclaration in the params). Otherwise, we might post-filter the result list to remove any items that are declarations when showing references.

  _Note:_ Many of these LSP settings require careful hooking into Neovim’s LSP client. The implementation will likely set global or buffer-local LSP handler overrides or use plugins. For the spec, it’s enough to note that we will **honor Helix’s LSP toggles** by configuring Neovim’s LSP accordingly (either via handlers, plugin settings, or conditional logic around LSP setup).
